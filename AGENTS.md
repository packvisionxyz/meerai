# AGENTS.md

Rust workspace for Pack Vision's terminal coding-agent harness: eleven library crates plus the `meerai` binary (built by `meerai-cli`). Milestones M1–M13 of `docs/harness-spec.md` are landed: session log, `AgentEvent` v2 item protocol, coding & retrieval tools (`repo_map`, `lsp`, `search_as_code`), policy engine (with default sensitive-file denials), context engine, prompt composition, subagent runtime (`subagent-run` + built-in/custom child sessions), CLI session forking (`--fork`, `sessions fork`), project-root config discovery, TUI session replay, configurable session retention (`sessions.auto_prune_days`), tool-output redaction, OS sandbox (`ExecutionWorld`), heuristic injection screening, OS keychain fallback store, `cargo-deny` CI audit, conditional release signing, [docs/threat-model.md](docs/threat-model.md), and agents/skills discovery. Checkpoints (M6) v1 and hooks (M7) v1 have landed; project hooks require explicit trust through a one-time TTY prompt, `meerai hooks trust`, or user settings. M13 is landed for `agy`: `--acp`, `/acp`, `acp doctor`, the `ACP:agy` badge and `agy (acp)` header, and `session/load` resume. OpenCode/Claude presets and M14 remain backlog.

## Commands

```sh
cargo fmt --all                                # rustfmt: edition 2024, max_width 100
cargo clippy --workspace --all-targets         # rust-analyzer checks with clippy
cargo test --workspace
cargo test -p meerai-macros --test derive_toolset_pass   # single integration test file
cargo test -p meerai-macros test_snapshot                # single test by name
cargo check -p meerai-cli --no-default-features          # headless-only build surface
cargo check -p meerai-tui --no-default-features          # TUI without reqwest/update
make verify                                    # fmt --check + clippy + test (alias: make ci)
```

- Verify order: `fmt -> clippy -> test`. CI (`.github/workflows/ci.yml`) runs the same gate on `ubuntu-24.04` for pushes and pull requests to `main`.
- CI has no Windows runner: `cmd /C` and Windows session-id rules are unit-tested, not exercised on a Windows host.
- Toolchain is pinned to Rust 1.100.0 (`rust-toolchain.toml`), edition 2024, `rust-version = "1.100"`; rustup installs it automatically.
- `release.yml` re-runs the gate before building five targets. It rejects a `v*` tag that does not match `[workspace.package] version`.
- `meerai-macros` snapshots update with `cargo insta review` or `INSTA_UPDATE=always cargo test -p meerai-macros`.

## Workspace layout

Dependency spine: `core -> macros`, `core -> session -> agents -> cli`, `core -> policy -> agents/common/tui`, `core -> meerai-tools -> cli`, `common -> client -> tui/cli`, `client -> providers -> cli`. Target layout is in `docs/architecture.md`.

- `meerai-core` — `Toolset` trait (`effect_of`, `effect_of_call`, `permission_spec`, `should_spill_output`, `invoke_structured`), `ToolOutput::{Text,Fail,Stop}`, `ToolError`, `EffectClass`, `PermissionAction`, `ApprovalPreview`, `GrantScope`, `ToolObservation`, `ToolRun`, `FileDiff`, shared `text`/`env`/`fs_perms` helpers; re-exports `genai`, `async_trait`, `schemars::JsonSchema`. `doctest = false`.
- `meerai-macros` — proc-macros `#[tool]` and `#[derive(Toolset)]` (darling + syn + quote; test-only deps are dev-dependencies).
- `meerai-session` — append-only `SessionEvent` log (`session.v<N>.jsonl` sealed to `.jsonl.zstd`), `meta.json`, crash recovery, `derive_messages`, fork/rewind (`latest_closed_turn`, `fork_latest`, `create_child`), snapshot store for rewind (`snapshots/<turn-id>/manifest.json` + blobs), blob store, spill, compaction primitives, session listing/deletion/pruning.
- `meerai-policy` — `PolicyEngine`: ordered action/resource/effect rules (globset, last match wins), `ApprovalMode`, grants, YAML parsing.
- `meerai-tools` — `code` (`CodeTools` with `read_file`, `write_file`, `edit_file`, `list_dir`, `grep`, `glob`, `shell`, path guards, unified diffs, `ToolRun` observations, secret env scrub, shared `workspace_search`), `repo_map` (`RepoMapToolset` / `retrieval-repo_map`, tree-sitter + PageRank, built with `#[derive(Toolset)]`), `lsp` (`LspToolset` / `lsp-*` stdio JSON-RPC), and `search_as_code` (`SearchAsCodeToolset` / `sac-run_script`).
- `meerai-common` — `AppSettings` (`settings.yml`), project-root discovery (`find_project_root`) plus project settings load/merge (`load_project_settings`, `merge_project_settings`), markdown agent/skill discovery (`definitions`: `load_definitions`, `AgentDefinition`, `SkillDefinition`, `DefinitionSource`), and hook configuration (`hooks`: `HookEvent`, `HookEntry`, `load_hooks`).
- `meerai-client` — client-facing provider surface: `ProviderCatalog` + bundled `providers.yml`, per-model metadata (`models:` entries: `context_window`, `input_cost_per_mtok`, `output_cost_per_mtok`; `ProviderCatalog::model_info`), `RuntimeProviderState`, `KeyStatus`, `SecretStore` contract, `MemorySecretStore`, and auth listing.
- `meerai-providers` — `genai` client factory plus native secret stores (`auth.json`, OS keychain); re-exports the `meerai-client` surface.
- `meerai-agents` — `MultiTurnAgent`, `AgentHarness`/`HarnessConfig` (including `TokenPricing`), `AgentEvent` v2, `intercept` (`Interceptor`, `StepPlan`, `ToolPlan`, `ToolContext`, `ToolOutcome`, `StepAction`, `TurnStopAction`, async `before_tool`), the hook engine (`hooks`: `HookEngine`, `HookContext`, `HookReport`, `HookFired` logging), the `question-ask` tool (`question.rs`) with `QuestionAsked`/`AnswerQuestion`, `prompt::{BASE_SYSTEM_PROMPT, compose_system_prompt}`, `spawn_worker`, `subagent` runtime (`SubagentToolset`, built-ins `build`/`plan`/`explore`/`general`, child sessions, forwarded approvals), and tool-output redaction (`redact.rs`).
- `meerai-tui` — modal TUI library split into `ui/` panel modules and `app/` modules, with transcript replay, tabs, subagent items, `/agent`/`/skill`, the `@` Mentions popup, and the `workspace::WorkspaceQuery` seam (no `meerai-tools` or `meerai-providers` dependency).
- `meerai-cli` — `meerai` binary: CLI flags (`--fork`), headless runner, `auth`/`sessions` (`list`/`rm`/`prune`/`fork`) subcommands, `hooks` (`trust`/`untrust`/`status`), and TUI launcher.
- `meerai-acp` — ACP client bridge: `AGY` preset (`agy acp`), `connect`/`connect_with`, `AcpHandshake`, typed `AcpEvent` stream, `AcpWorker` (`AgentCommand`/`AgentEvent` + session log), permission replies, cancel, `session/load`, stderr tail. The CLI/TUI depend on it; the external agent keeps its own tools and policy.

## Tool macro conventions (non-obvious)

- `#[derive(Toolset)]` on a struct requires you to hand-write `impl <Struct>Invoke for <Struct>` with `async fn <snake_case_tool>(&self, args: &<Params>) -> Result<ToolOutput, ToolError>` per tool declared in the `#[toolset(...)]` attribute. The generated `Invoke` trait is private to the expansion site — impl it in the same module.
- `CodeTools` (`meerai-tools`) does **not** use `#[derive(Toolset)]`; it hand-writes `impl Toolset` with `definition`, `contain`, `effect_of`, `invoke`, and `invoke_structured`.
- `RepoMapToolset` is the production consumer of `#[derive(Toolset)]`. It sets `#[toolset(name = "retrieval", tool(name = "Repo Map", ...))]`, which keeps the runtime name `retrieval-repo_map`, and hand-writes `impl RetrievalInvoke` (the trait is named from the toolset name, not the struct). Generated schemas use `SchemaSettings::draft07()`. Do not add a second `impl Toolset` for it.
- Generated code references `meerai_core`, `schemars`, and `serde_json` by absolute path: consuming crates need all three as direct dependencies.
- Runtime tool-call names are `"<toolset_snake>-<tool_snake>"`, e.g. `MyToolset` + "Get Weather" -> `my_toolset-get_weather`. `Toolset::name()` is the snake_case toolset name.
- `#[tool(name = "Get Weather", ...)]` on a free async fn generates a `<PascalName>Toolset` unit struct wrapping `#[derive(Toolset)]` (e.g. `get_weather` fn -> `GetWeatherToolset`, runtime name `get_weather-get_weather`).
- The `#[tool]` attribute infers params from the fn's first argument type, not from the attribute (`get_weather` takes `args: &GetWeatherArgs` without declaring `params`).
- Params types must derive `JsonSchema` from **schemars 1.x** (workspace `schemars = "1"`, locked at `1.2.3`) — not schemars 0.8. Use `#[derive(schemars::JsonSchema)]`; there is no schema derive in `meerai-macros`.
- Tool schemas are generated with `schemars::generate::SchemaSettings::draft07()` (`meerai-tools/src/code/mod.rs::definition_for`), not through the macro.
- Macro expansion is snapshot-tested with insta (`meerai-macros/src/tool/snapshots/`), output pretty-printed via prettyplease.

## Config & environment

- Runtime config is `settings.yml` (active provider/model, `approval_mode`, `permissions`, `context`, `sessions`) plus `providers.yml` overrides in the config dir: `$XDG_CONFIG_HOME/meerai` or `~/.config/meerai` (`meerai_common::settings::default_config_dir`). `providers.yml` also accepts a `models:` list; the resolved model's `context_window` replaces the default only when `context.context_window_tokens` is unset, and pricing fills `est_cost_usd` only when both per-million prices are present.
- Project config is `<project-root>/.meerai/settings.yml`. `find_project_root` walks up from the process CWD to the nearest directory holding `.git` (directory or file) or `.meerai/settings.yml`; if none match, the CWD is used. The file is merged over the user settings by `load_project_settings` + `merge_project_settings` in `meerai-cli/src/main.rs`. Tools and sessions still use the CWD as the workspace, so a run from a subdirectory applies the repository-root policy. Only `permissions` and `context` apply; `active_provider`, `active_model`, `providers`, `approval_mode`, and `sessions` are ignored with a warning. Project `permissions` merge as `ask` rules → user rules → `deny` rules; `allow` is dropped with a warning. `context` overrides field by field, and `max_session_tokens`/`max_turn_secs` are clamped against user values (a project cannot raise a cap or disable the turn clock). A malformed file prints a warning and is ignored.
- `sessions.auto_prune_days` (user config only) opts into startup pruning; `sessions.keep` (default 0) spares the newest N sessions and the active session is always spared. Pruning prints `Pruned N sessions (older than N days)` on stderr; errors warn and never abort. Without `auto_prune_days`, retention is manual (`sessions prune`). A project `sessions` block is ignored with a warning.
- Agent/skill discovery is read-only and starts at the project root: `.agents/agents/*.md` then `.claude/agents/*.md`; `.agents/skills/*/SKILL.md` then `.claude/skills/*/SKILL.md`. `.agents` wins a duplicate id (warning names both paths); output is sorted by id. `.meerai` is config, sessions, and instructions only: never scan or create `.meerai/agents` or `.meerai/skills`, and never copy definitions. Frontmatter is `name`, `description`, `model`, `steps`, `mode`; `tools`/`permissions`/`allowed-tools` warn and are not applied; invalid frontmatter warns and skips. A missing frontmatter uses the file name (agent) or directory name (skill) and the body. Only `SKILL.md` text is used. Definitions are untrusted prompt text: they grant no tools or permissions.
- Hooks are user and project shell commands. User hooks load from `<config-dir>/hooks.json` (`~/.config/meerai/hooks.json`). Project hooks load from `<project-root>/.meerai/hooks.json` only when `MEERAI_TRUST_PROJECT_HOOKS=1|true|yes`, user `hooks.trust_project: true`, or the canonical project root is in user `hooks.trusted_projects`. `meerai hooks trust|untrust|status` manages the list; the TUI path also prompts once on a terminal. A project file cannot trust itself. `hooks.enabled: false` disables both. Files accept a JSON list or `{ "hooks": [...] }`; entries are `{ event, matcher, if, command, timeout_ms, fail_closed }`. Events are `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PostToolUseFailure`, `Stop`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop`, and `SessionEnd`. Hooks run concurrently with a 10 s default timeout (60 s max), receive JSON on stdin, exit `0` = pass, exit `2` = block, other = warning; `fail_closed` applies to failures. Every firing logs `HookFired` and emits `AgentEvent::HookCompleted`; the TUI appends a System line, and headless NDJSON carries the event. `/reload` re-reads both hook files and sends `AgentCommand::SetHooks`. A `timeout_ms` outside 1..60000 warns at load time and resets to the default.
- Hooks may tighten or ask, never loosen. `PreToolUse`/`PermissionRequest` `allow` overrides only a tier-default `Ask`; it cannot override `plan`, an explicit `deny`/`ask` rule, or the forced outside-workspace `Ask`. In `plan`, a hook `Deny` can refuse an allowed read. `Stop` block continues the turn once. `UserPromptSubmit` block fails the turn with `ErrorCode::Config`. Hooks run host commands outside the OS sandbox.
- ACP is an external engine. `--acp` starts an `agy acp` session; `meerai acp doctor` prints the handshake; `/acp` opens a new ACP tab. ACP turns are driven by `AcpWorker` and mirrored into `SessionEvent`s with `harness: acp:agy` and `remote_session_id`. `--continue`/`--resume` of an ACP session uses `session/load`. ACP permissions use `ApprovalKind::ExternalAgent`; the decision is forwarded to the external agent and is advisory. `plan` mode refuses `--acp`. ACP does not consult `PolicyEngine`, grants, path guards, redaction, or `ExecutionWorld`.
- `meerai-tui` has a default `update` feature (reqwest, GitHub release check). `meerai-cli` has a default `tui` feature. `--no-default-features` builds a headless binary without ratatui, git2, comrak, or the TUI crate; genai still pulls reqwest.
- `context.summarizer_model` (optional, full `provider:model` spec) selects the compaction-summary model; the default is the session model. Summarizer usage counts toward `context.max_session_tokens`.
- `context.post_edit_diagnostics` (optional bool, default false) runs `lsp-get_diagnostics` after a successful `code-edit_file` or `code-write_file`. It is policy-gated as a read, uses a 5 s timeout, screens and caps the text, and logs one `RuntimeContext` message per edit. It never prompts and never recourses into an edit.
- `theme` (user, project, and working-directory `.meerai/settings.yml`) overrides palette tokens field by field. Accepted values are `#rgb`, `#rrggbb`, or a terminal color name. A project or working-directory theme changes presentation only. `meerai_tui::theme::install` sets the process palette once; render reads it through `theme::p()`.
- API keys live in `auth.json` in the data dir: `$XDG_DATA_HOME/meerai` or `~/.local/share/meerai`. `meerai auth login|logout` writes it. `auth.json` is `0600` on Unix.
- Key resolution order: stored `auth.json` → configured `api_key` → the provider's `env_vars` from the bundled `meerai-client/providers.yml` (for example `OPENROUTER_API_KEY`/`OPEN_ROUTER_API_KEY`, `GEMINI_API_KEY`, `OPENAI_API_KEY`). No API-key assert exists; a missing required key fails in the genai auth resolver.
- `settings.yml` secrets support `${VAR|default}` and `{env:VAR}` expansion (`settings::expand_config_secret`).
- Sessions default to `$XDG_DATA_HOME/meerai/sessions/<id>/` (`~/.local/share/meerai/sessions` when unset); `MEERAI_SESSION_DIR` overrides the root. `auth.json` and `open-tabs.json` use the same data root. `meerai-cli/src/main.rs` uses the global root.
- Session directories are `0700` and session files are `0600` on Unix; `meta.json` records cwd, git branch/SHA, title, model, optional `parent_session_id`, optional `harness`/`remote_session_id`, and created/updated times. `meerai sessions list|rm|prune|fork` manages them; `--continue` picks the most recently updated non-child session; `--fork <ID>` forks and immediately resumes. `--continue`/`--resume <ID>`/`--fork <ID>` work with or without `--prompt`: with `--prompt` they run headless, without it they start the TUI and replay the transcript.
- Startup deletes unused sessions (no `InputSource::User` message, no title, no parent session) through `prune_empty_sessions`; it skips the active session and child sessions, and never aborts the run.
- The `sac` script tool is registered only when `python3` or `node` exists at startup. `ScriptRuntime::detect()` prefers `python3`. `prompt::append_script_guidance` adds the "prefer one analysis script" rule; an injected language outside the detected runtime fails with a hint.
- Headless non-`--json` runs print `tokens: prompt=… completion=… total=…` on stderr after the turn. The counters are cumulative for the session and are seeded on resume from the last logged `UsageUpdated` entry.
- The agent sets the session title from the first user prompt (first non-empty line, 80 chars) and skips a session that already has a user message.
- `MEERAI_PROVIDER` / `MEERAI_MODEL` set default provider/model; CLI flags win.
- `.env` loading is opt-in: `MEERAI_LOAD_DOTENV=1|true|yes` or `--env-file <PATH>`. Nothing loads implicitly. `.env` is gitignored.

## Known traps

- Project config is found at the **repository root**, not the CWD: `find_project_root` walks up to the nearest `.git` (directory or file) or `.meerai/settings.yml`. Tools, sessions, and prompt injection still use the CWD as the workspace, so a run from a subdirectory keeps `code-*` paths CWD-relative while the policy comes from the root. Do not "fix" this by resolving the workspace to the project root.
- Agent/skill definitions are found at the **project root** too (`load_definitions(&project_root)` in `meerai-cli/src/main.rs`), not the CWD. `.agents` is the default source and beats `.claude` on a duplicate id; the warning names both paths. Output is sorted by id. There is **no** `.meerai/agents` or `.meerai/skills` discovery: `.meerai` is config, sessions, and instructions only. Do not add native definition directories, copy definitions into `.meerai`, or add an import lock.
- Definition loading is read-only. `load_definitions` reads `.agents/agents/*.md`, `.agents/skills/*/SKILL.md`, `.claude/agents/*.md`, and `.claude/skills/*/SKILL.md`; it writes nothing and skips symlinks with a warning. Only `SKILL.md` text is used; supporting skill files are never read.
- Frontmatter parsing: the file may start with `---`. A missing closing `---` or invalid YAML warns and skips the file. Missing frontmatter uses the file name (agent) or directory name (skill) as the id, and the whole body as the prompt. Fields are `name`, `description`, `model`, `steps`, `mode`. `tools`, `permissions`, and `allowed-tools` warn and are **not** applied. Unknown fields are ignored.
- Applying definitions is prompt-only. Startup `--agent`/`--skill` append to the system prompt; `--agent` takes one id (repeating it is an error) and every named id must exist. An agent `model` applies only when it has no `:` (colon implies a provider change and is ignored with a warning); precedence is `--model` → `MEERAI_MODEL` → agent `model` → settings/provider default. `steps`/`mode` print a note and are not applied. TUI `/agent`/`/skill` send `AgentCommand::ApplyAgent`/`ApplySkill`, which log a System instruction at the next step boundary; they do not edit the system prompt or grant tools/permissions. Typing `@` opens the Mentions popup (agents first, then skills, then files): rows show `<id>|agent` (purple accent) or `<id>|skill` (orange interactive) plus source/description, files show a path with no badge, and one id can appear as both kinds. Filter matches `@agent/<id>`, `@skill/<id>`, the bare id, and fuzzy prefixes; Up/Down or ctrl+p/ctrl+n move, Tab accepts, Enter accepts without submitting, Esc dismisses. Accepting inserts `@agent/<id> `, `@skill/<id> `, or `@path ` with one trailing space and stays in Insert; an exact agent/skill id keeps the popup open, an exact file path auto-dismisses. The composer renders a known accepted mention as `<id>` chip (bold purple accent for agent, bold orange interactive for skill) while the raw `@agent/<id>`/`@skill/<id>` stays in the input buffer and submit detection; unknown ids and partial tokens render as typed. On submit, skills apply before the agent, mentions are stripped, repeats apply once, and an unknown mention stays as text; a mention-only prompt applies definitions without a turn. `/agents` and `/skills` do not exist. Unknown or missing `/agent`/`/skill` ids print a System error and send nothing.
- `sessions prune` uses a strict `updated_at_ms < cutoff` test after skipping the newest `--keep N` sessions (default 0). Defaults are 30 days and keep 0; it prints `removed N sessions` and uses the global session root (`MEERAI_SESSION_DIR` aware). Automatic pruning is separate and opt-in: `sessions.auto_prune_days` with `sessions.keep` (default 0), excluding the active session, printing `Pruned N sessions (older than N days)`. A project `sessions` block is ignored; never let a project file control retention.
- Rewind is the only user-facing action. `AgentCommand` has no `Revert` variant and there is no `RevertApplied` session event. `AgentCommand::Rewind { turn_id, scope }` restores code from `Session::snapshot_store()` and/or calls `Session::rewind`, which closes open turns and appends one `RewindApplied { scope, restored, replaced }` event. The TUI sends `RewindScope::Both` from the message menu and the `/rewind` menu (second option: code only). Capture happens before write-class tools only: shell edits, external edits, gitignored files, symlinks, and files over 2 MiB are not restored; checkpoints are recovery, not version control.
- Questions are not approvals. `question-ask` uses `AgentEvent::QuestionAsked` and `AgentCommand::AnswerQuestion` under `AgentEvent::QuestionResolved`; the policy engine is not consulted, no grant is recorded, and headless auto-cancels. The `question-ask` tool is `EffectClass::Read`, runs before the rest of the batch, and is not registered for subagents.
- Extend the agent loop through `meerai_agents::intercept`, not by adding branches to `turn.rs`. `Interceptor::before_step` may stop a turn, async `before_tool` sees an authorized `ToolPlan`/`ToolContext` before execution, `after_tool` sees the post-redaction/post-spill `ToolOutcome` and may return a model-visible follow-up, and `turn_stopping` may continue the turn once. M6 checkpoint capture is the built-in `CheckpointInterceptor` on `before_tool`. M7 hooks do **not** use the interceptor chain: they use `HookEngine`, because they must await host processes at lifecycle points outside the loop. Do not force hooks into `Interceptor`.
- Hook trust is caller-side. `load_hooks` loads a project file only when the CLI passes `Some(path)`; the project file cannot set `hooks.trust_project` for itself. A project `hooks` block in `.meerai/settings.yml` is ignored with a warning. Trust is stored as canonical project paths in user `hooks.trusted_projects`; `meerai hooks trust|untrust` edits it. The interactive prompt runs only on the TUI path with a terminal stdin and defaults to no; non-interactive runs must use the env flag, the user setting, or the trusted list. Do not add an implicit trust prompt.
- Hook output is untrusted. `HookFired` logs `event`, `decision`, and `HookDetail`; a `PostToolUse` block reason reaches the model as a runtime message. `HookReport::reason()` also returns a reason for `Pass` (for example a non-zero exit warning); callers must not treat a `Pass` reason as a block. Keep the reason caps; hooks run arbitrary host commands and are not sandboxed.
- ACP `session/load` replays history as `TextDelta` notifications **before** `Connected`. `AcpWorker` drains events up to `Connected` so the local transcript is the source; do not process pre-`Connected` updates as a new turn.
- `Session::fork` does not copy `harness`/`remote_session_id`. The CLI fork path reads the source harness and starts a new ACP session (`AcpStart::New`) instead of loading the source remote session.
- The ACP SDK cannot set the child working directory. `--acp` runs the adapter from the process CWD, which is the workspace; do not change the process CWD globally.
- ACP `plan` mode is refused: the external agent cannot be made read-only. Other `--mode` values are ignored with a warning; the adapter controls its own modes.
- `SessionEvent::HookFired` carries an additive `detail: Option<HookDetail>`; older logs without it still deserialize. Keep new hook data inside `HookDetail` or add fields with `#[serde(default)]`; do not retype `event`/`decision` in place.
- Provider model metadata belongs in `ProviderCatalog` (`ModelInfo`), not in `HarnessConfig`. The catalog supplies defaults only; explicit `context.context_window_tokens` still wins, and pricing is never invented in the bundled `providers.yml`.
- `meerai-tui` must not depend on `meerai-tools` or `meerai-providers` again. File listing and content search go through `workspace::WorkspaceQuery`; provider catalog, key status, and secret contracts go through `meerai-client`. A remote client can replace the workspace query through `TuiLaunchConfig::workspace_query`.
- `events.rs` (`AgentEvent` v2, `SessionItem`, `ItemDelta`) and the `SessionEvent` vocabulary in `meerai-session` (plus its id newtypes) are frozen contracts: change them additively only. Renaming or removing a variant breaks the TUI fold, headless NDJSON, and persisted session logs.
- Serde tagging pitfall: internally tagged enums (`tag = "type"` alone) cannot hold newtype variants with bare strings. `ItemDelta`/`AgentCommand`/`ContentBlock` use adjacent tagging (`tag = "type", content = "data"`); keep that shape when adding string-carrying variants.
- `-p` is **provider**, not prompt. Headless prompt input is `--prompt` (alias `--print`); `--json` requires it.
- The approval mode is stored per session in `meta.json` (`SessionMeta::approval_mode`, set by `Session::set_approval_mode`). Precedence is `--mode` > stored session mode > `settings.approval_mode` > `ask`. `/mode` persists through `SetPermissionMode` (the worker writes meta), forks inherit the source mode, and restored tabs load each session's own mode. A project settings file cannot set `approval_mode`.
- Approval modes are `plan`, `ask`, `auto-edit`, `auto-approve` (alias `auto`), and `yolo`. `auto-approve` allows every tier default (read/write/execute/external) but still honors explicit `ask` and `deny` rules, including project rules. `yolo` ignores `ask` rules and only honors `deny`. Switch with `--mode`, `approval_mode` in `settings.yml`, `/mode <name>`, or the ctrl+p palette. `plan` denies non-read before rules. Statusline badges are `PLAN`, `ASK`, `EDIT`, `AUTO`, `YOLO`.
- Headless approvals: a tool-call approval fails fast with exit `2` plus a hint to use `--mode auto-edit|auto-approve|yolo` or the TUI. A Spend approval (session token cap) instead prints how to raise/unset `context.max_session_tokens`, declines, and exits `1` because the turn ends `Failed { Budget }`. Completed is `0`; other failures are `1`.
- `plan` mode is hard read-only: writes, execute, and external effects are denied before rules and grants are consulted. `yolo` still honors explicit `deny` rules. Grant resources match literally; rule resources use globs.
- `Approve { request_id, decision, scope }` carries an optional `GrantScope`. `AcceptForSession` always records a Session grant. The TUI sends `scope: None` for `y`/Enter and `scope: Some(Turn)` for `t`; `a` maps to `AcceptForSession`. Turn grants are cleared at turn end.
- `AgentCommand` has **no** `Rewind` or `Fork` variant. TUI resume and transcript replay **do** exist: without `--prompt`, `--continue`/`--resume <ID>` open the session and replay it. Session replay lives in `meerai_session::replay` (`replay_from_events`, `session_usage_from_events`); the TUI converts `ReplayEntry` into its `TranscriptEntry` view and keeps `user_turn_map`. `replay_from_events` keeps user/steering messages, assistant text/reasoning, tool calls/results, and compaction markers; system and runtime events are skipped, and unmatched tool calls become `Cancelled`. `set_harness` and `session_usage_from_events` seed token counters from the last logged `UsageUpdated`.
- Coding-tool runtime names are `code-<tool>` (`code-read_file`, `code-edit_file`, ...). `Toolset::contain`/`effect_of` match that prefix; permission checks in the agent strip `code-` or `code_` before mapping the tool name.
- With a harness but no command channel (`MultiTurnAgent::prompt` / `prompt_streaming`), every `Decision::Ask` auto-declines: `await_decision` has no receiver and returns `Decline`. The TUI uses `spawn_worker`, which supplies the inbox.
- When a harness is attached, requests come from `session.derive_messages(...)`, not `chat_history`; `chat_history` is still maintained as a mirror. Do not treat it as the source of truth.
- `max_turn_secs` defaults to 1800 when a harness is attached; `0` disables it. Without a harness the deadline is `0`. Provider retries are 3 attempts total with 250/500 ms backoff and only for non-transient-marked errors; tool retries use a fixed 250 ms sleep and `max_retries` (default 3).
- System prompt composition is not the same as the projection: `BASE_SYSTEM_PROMPT` + `--system` + root `AGENTS.md` + `.meerai/instructions.md` (32 KiB/file, 64 KiB block) are sent via `ChatRequest::with_system`, while scoped `AGENTS.md` files (16 KiB, max 8 per turn) are injected as `RuntimeContext` user messages once per turn. The agent appends an `Active model: <genai-spec>` identity line to the sent prompt and to the logged `SystemMessage`; `set_model` refreshes it, so model-identity questions need no tool call. `--skill`/`--agent` append definition text to the same system prompt at startup; TUI apply commands use System-sourced user messages instead.
- Project permissions merge as `ask` rules → user rules → `deny` rules. `allow` entries are dropped with a warning. A project `ask` cannot downgrade a user `deny`, even with a wildcard resource, because user rules match later; it tightens the mode default only where the user has no matching rule. A project `deny` always adds a denial after user rules. An invalid entry or non-list shape drops the whole project `permissions` block with a warning. Do not "fix" this by keeping `allow` or by appending project `ask` after user rules. `merge_max_session_tokens`/`merge_max_turn_secs` clamp project budgets; project `0` cannot disable the turn clock.
- Tool-output redaction is best effort and runs in the agent after a tool run and before spill, session log, `ItemCompleted`, or model text: `redact_run` in `meerai-agents/src/redact.rs` rewrites observation stdout/stderr/hint, `ToolOutput` text, and `FileChange` unified diffs; dispatch failures are redacted with `redact_text`. The original secret is discarded; do not add a log-only copy. Paths are not redacted.
- `context.summarizer_model` is used only for compaction summaries; it defaults to the session model and its usage still counts toward the session token cap.
- Session titles come from the first user prompt (80 chars, single line). `new_session_title` skips when the session already has a title or any `InputSource::User` message.
- `/rewind` is available only when no turn is running and there is a user turn. It opens the rewind menu; conversation restore truncates the visible transcript before the turn.
- `ctrl+p`/`ctrl+shift+p` opens the command palette (`ActiveModal::CommandPalette`, `app/palette.rs`) unless the completion popup is open; there it keeps its Up/Down behavior. Rows are grouped by `PaletteCommand::section` (Session, Model, Approval, View, Turn, App) and the hint column shows the shortcut text via `PaletteCommand::display_hint`; key hints and slash-command hints use different styles. Palette rows run through `handle_slash_command` (or a `PaletteAction` for tab/copy); do not duplicate command logic in the palette. Menu shortcuts: `ctrl+s` sessions, `ctrl+o` models, `ctrl+a` provider connect, `ctrl+e` first file diff, `ctrl+f` search, `ctrl+b` sidebar, `ctrl+w` close tab. Labels come from `app::ctrl_label`, which always renders `ctrl+<key>`; `ctrl+t` is not bound.
- Tool rows use action labels from `activity_verbs` in `ui/transcript.rs` (`Reading`/`Read`, `Running`/`Ran`, `Editing`/`Edited`, `Searching`/`Searched`), a `+`/`-` expand marker, and no click hint. Hover paints the raised band only on expandable tool, command, subagent, and error rows; the digest and thought headers highlight their text instead. Edits and writes expand to a unified diff (`diff::parse_unified_diff`, 3 context lines from the tool output) with the path and `+N -N` counts in the header, colored additions/removals, and syntax highlighting from the shared `syntax.rs` module. Finished rows use `faint`/`muted` text; a failed row keeps `error` in the badge. Collapsed non-edit runs show the last 8 output lines; expand shows the full output (capped at 200 lines).
- Tool arguments are normalized before parsing: `normalized_tool_args` (agent) and `parse_args` (tools) call `meerai_core::lenient::normalize_tool_arguments`, which unwraps JSON strings that contain JSON (including escaped text such as `{\"command\": ...}`) and wrapper objects (`{"arguments": ...}`, `{"args": ...}`, `{"tool_input": ...}`), up to eight levels. Regex-free unescaping only runs after a strict parse fails. Tool args also accept common field aliases (`file`/`file_path` for `path`, `cmd` for `command`, `old_text`/`new_text`, `column` for `character`, ...). `ToolError::WrongArguments` and `InvalidFunctionName` are not retried (one attempt, then the failure is reported).
- The turn loop logs `AssistantMessage` before executing tools. Every planned call logs a `ToolResult` even when refused, cancelled, or failed, so the next request always carries the calls and results. `collect_stream` merges `ChatStreamEvent::ToolCallChunk` calls with `StreamEnd::captured_tool_calls`; a later chunk or the captured call replaces an earlier partial chunk (adapters stream empty args first, then accumulate). Identical tool batches repeat a diagnostic at the third repeat and fail the turn with `ErrorCode::LoopDetected` at the fifth.
- Safe shell commands are auto-approved. `shell_safety::command_is_safe` splits on unquoted `&&`, `;`, and `|` (quote-aware, so a quoted `grep 'a|b'` or `\|` does not split) and requires every segment to be a read-only program (`ls`, `cat`, `rg`, `cd`, `git status|diff|log|show|branch --list|stash list|remote -v`, ...). It rejects `||`, background `&`, redirects, `$()`, backticks, mutation flags, env prefixes, absolute paths, `..`, `~`, and any pipe into an interpreter. `sed` is allowed only when it is read-only: `-i`/`--in-place`/`-f` and `w`/`e` scripts are rejected. The agent converts `Decision::Ask` to `Allow` only for `PermissionAction::Shell` in `ask`/`auto-edit` and only when `PolicyEngine::matched_effect` is `None`; an explicit `ask` or `deny` rule always wins, so a wildcard `{ action: shell, resource: "*", effect: ask }` disables auto-approval. `plan` still denies and `yolo` is unchanged. Build and test commands still ask because they execute code. Chaining is allowed and preferred over one command per call, because each extra tool call re-sends the conversation and costs more tokens. Keep the list conservative.
- Mouse toggles happen on mouse-up only. `pending_toggle` is captured on press and cleared on drag, so dragging over expanded content never collapses it.
- Clicking a user message opens `ActiveModal::UserMessageActions` with `Rewind`, `Copy`, and `Fork` (keys `w`/`c`/`f` or Enter). Copy uses the clipboard path. Rewind sends `AgentCommand::Rewind { turn_id, scope: Both }` and truncates the transcript before the message. Fork calls `SessionOpener::fork_session` at the previous turn (or `create_session` when there is no previous turn) and puts the message in the new tab's composer without sending it. Turn ids come from `SessionTab::user_turns`, fed live on `TurnStarted` and from events by `user_turn_map`.
- Open modals block all mouse input except scroll. Do not let clicks behind a dialog start a selection or toggle an entry.
- The terminal window title shows status text plus one single-width dot: `meerai ●` (idle), `meerai — working ●` (a turn runs), `meerai — approval needed ●` (pending approval). It sets only the window title (OSC 2) and, on iTerm2, the tab color (OSC 6: green idle, amber working, red approval). An approval request additionally rings the bell and sends an OSC 9 notification. The event loop derives the aggregate status from all tabs. `MEERAI_NO_NOTIFY=1` disables title, tab color, bell, and notification; teardown restores the title and tab color.
- The layout has no rule above the composer. The composer and statusline are one surface panel with one row and one column of padding; the transcript has one row and two columns of padding. The sidebar is two panels: `surface` for the session block, a one-row gap, then `surface_high` for file changes. The session block shows `session`, `provider`, `model`, `auth`, and `dir` (home shortened to `~`); do not duplicate running state, tokens, or speed there because the statusline owns them. The transcript header is one line (`meerai provider/model [auth]`).
- Dialog widths are capped: approval `≤72`, provider `≤64`, API key `64`, model `60`, session list `≤68`, command palette `46..58`, message menu `40`. Diff and search stay wide. Keep new dialogs narrow.
- Tool rows are expandable even while running. Expanding shows pretty-printed tool arguments, then the script when present, then the output. Collapsed runs show the last 8 output lines.
- `/reload` re-reads user and project settings, the theme palette (`theme::set`), definitions, policy rules, context budgets, and the composed system prompt. It keeps every session, transcript, and tab; it sends `AgentCommand::Reload` to each tab. Provider catalog, API keys, and the approval mode are not reloaded (use `/connect`, `/model`, `/mode`); the update check is startup-only.
- The session picker (`/sessions`) deletes with `ctrl+d` after a second `ctrl+d` confirmation (`session_delete_confirm`). It refuses open sessions ("close the tab first"), sends `PendingSessionAction::DeleteSession`, then refreshes the list. Deletion removes the session directory through `SessionOpener::delete_session`; it never deletes a session that is open in a tab.
- Tabs: each tab has a `×` close zone (`TabHitKind::CloseTab`). Closing a tab quits its worker but keeps the session on disk. `meerai-tui/src/tabs.rs` saves session ids and the active index per workspace to `<data>/open-tabs.json`; `run_tui` enables persistence (`tab_persistence`), so tests never write it. On TUI start with no `--prompt`/`--continue`/`--resume`/`--fork`, the CLI restores the first saved session as the initial tab and queues the rest as `OpenSessionId`. The saved active index is not restored.
- Update checks are notification-only. `meerai-tui/src/update.rs` reads the latest GitHub release tag (3 s timeout) at TUI startup; `MEERAI_NO_UPDATE_CHECK=1` disables it. When a newer version exists, the statusline shows `update vX (/update)` with a click hit zone, `/update` prints the install hint, and the palette has "Check for updates". meerai never installs an update on its own.
- `sac-run_script` arguments are parsed for display: the header preview shows the language and first script line, and the expanded run shows the script lines (`›`) before the output (`│`).
- Outside-workspace access is approval-gated. `outside_workspace` (agent) detects absolute paths and `..`; the agent forces `Decision::Ask` unless the mode is `yolo` or a session grant covers the path. The preview adds an `outside workspace:` line. Approval calls `Toolset::grant_path_root`, which adds an extra root to `CodeTools`; extra roots widen read/write resolution and the shell sandbox. `outside_grants` is session-scoped and cleared on reset/rewind. Do not bypass the path guard for unapproved paths.
- Composer clicks move the cursor and start a drag selection (`composer_pointer_down`, `composer_drag_anchor`). Drag (`Drag` or `Moved` while an anchor is held) sets `composer_selection`, paints it with `surface_high`, and never copies; Backspace/Delete or typing deletes the selection. Clicks anywhere in `composer_block_area` are captured so they cannot start a transcript selection. `display_col_to_char_index` and `display_pos_for_byte` map display columns through `@` mention chips; keep them in sync with `render_composer_line`.
- Thought blocks are click-only: no key binding toggles them. The header reads `Thinking` while the item streams and `Thought` after the turn ends, with a `+`/`-` expand marker and a text hover highlight.
- `build_transcript_lines` emits one per-turn digest under the user message (`TurnDigest` in `ui/transcript.rs`). `code-shell`/`sac-run_script` count as commands, `code-read_file` as reads, `code-write_file`/`code-edit_file` as edits, `subagent-run` as agents, and all other tools (grep, glob, list_dir, lsp, repo_map, question-ask) as tools; non-empty reasoning counts as thoughts. Keep that mapping in `ui/transcript.rs` when tool names change. Active groups use gerunds (`Running 1 · Reading 2`); finished groups use noun counts (`1 command · 2 reads`). The digest is a collapse toggle: every turn hides its tool rows, thought blocks, and subagent rows behind the digest line by default, even while running. Clicking the digest expands or collapses that turn (`+`/`-` marker, `SessionTab::turn_activity`, keyed by user entry index, cleared on rewind/`/clear`/`/reset`). Response text, errors, and system notices stay visible; a thought header attached to a visible response hides with the turn.
- Subagent rows are expandable when they carry a `child_session_id`. `SessionItem::SubagentRun` carries the id additively (`#[serde(default)]`), and `ItemStarted` is emitted after the child session exists. Expanding loads the child log through `SessionOpener::read_session_events` and folds it with `transcript_from_events`; while the child runs, the nested view refreshes about once per second (`queue_child_session_refreshes`). Replay converts a `subagent-run` tool result whose hint carries `child_session_id:` into the same Subagent entry. The statusline shows running agent names instead of `subagent-run`. The nested view is display-only: its lines share the parent hit zone, so any click collapses the group.
- While a turn runs, `Enter` appends to `SessionTab::queued` and sends nothing; `SessionTab::flush_queued` sends the next prompt on `TurnCompleted` or `Error`. `ctrl+g` steers the oldest queued message (or the current draft) at the next step boundary. Queue state is display-only and never enters the session log. Do not send a second `SubmitPrompt` while `is_running`.
- On Windows the shell tool runs `cmd /C`; on Unix it runs `sh -c`. Known provider key variables and names ending in `_API_KEY`, `_API_TOKEN`, `_ACCESS_TOKEN`, `_SECRET`, `_SECRET_KEY`, or `_PRIVATE_KEY` are removed from the child environment. Tool output is pattern-redacted, not guaranteed secret-free.
- **Security posture (M11 landed with explicit caveats).** `ExecutionWorld` runs macOS Seatbelt and Linux bubblewrap when available, falling back with a startup warning to Phase-1 path guards on Windows or nested/restricted hosts. `CodeTools` (`read_file`/`write_file`/`edit_file`/`grep`/`glob`/`list_dir`) and `PolicyEngine::default_sensitive_rules` block `.env*`, key, secret config, and credential files. `KeychainSecretStore` prefers native OS keychains (`security` / `secret-tool`) with `0600` `auth.json` fallback. `redact_run` and `screen_run` are best-effort regex/heuristic layers, not guarantees. `ci.yml` and `release.yml` run `cargo-deny` (`deny.toml`); release signing steps in `release.yml` are conditional on repository signing secrets (`APPLE_CERTIFICATE` / `WINDOWS_CERTIFICATE`) and remain unsigned until those secrets exist. Threat model lives in [docs/threat-model.md](docs/threat-model.md).
- M12 definitions are untrusted repository prompt text. They cannot run tools, map permissions, or imply a sandbox. `.agents`/`.claude` content reaches the model, so review it like code; do not describe definition loading as a security control.

## Commit rule

- One commit, one line. Squash every change set into a single commit whose message is a single line: no body, no bullet list, no paragraphs.
- Never add a second commit above the base, and never merge.
- Never edit, stage, or commit `.opencode/` or `opencode.jsonc`; both are gitignored local tooling.

## Code style

- Default to **no comments** (including doc comments). Only add a comment when it is truly crucial — i.e. changing that code without knowing the invariant would break the application.
- Treat every struct you touch as a design review. Choose the narrowest correct type for each field: an enum over a `bool` or a stringly-typed flag, a newtype over a bare primitive when the value has invariants, and `Option<T>` only when absence is a real state. Group related fields, order them by identity, then state, then metadata, and refactor the struct instead of appending fields to its end. Keep serde names and order stable unless the change is intentional.

## Communication

- Respond to the user in ASD-STE100 Simplified Technical English: short sentences, one idea per sentence, active voice, no idioms.
- Use BLUF (Bottom Line Up Front): state the result or decision first, then the support.
- Use SBAR (Situation, Background, Assessment, Recommendation) for handovers and status updates.
- These rules do not apply to code, generated files, commit/PR messages, or when the user asks otherwise.
